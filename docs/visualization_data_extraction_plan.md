# 国公立大学院・卒業者データ抽出計画

## 概要

EChartsとFastAPIによる可視化の前処理として、`data/tiers/` に掲載された大学院のうち、理系研究科に関する2025年度データだけを抽出する。

この計画の対象はデータ抽出までとする。API、画面、グラフ、データベースは実装対象に含めない。

## 決定事項

- tiersにある大学院名は、表記を正規化すると32校になる。
- R07データで一致する23校を抽出対象とする。
- R07データにない私立9校は抽出せず、理由付きで対象校マスタに残す。
- 理工、情報、農水産、生命、環境、医歯薬、保健、獣医を理系に含める。
- 文理融合分野を含む採否は、研究科名のキーワードだけで決めず、明示的な採用リストで管理する。
- 研究科には8種類の分野カテゴリを付与する。
- 元CSVごとの列構造を維持し、可視化に必要な識別列だけを末尾に追加する。
- 研究科の集計行と専攻明細行はどちらも保持し、集計レベルを列で区別する。
- 抽出結果は `data/processed/univ_portraits_R07/` に出力する。

## 入力データ

### 対象大学の定義

| ファイル | 用途 |
| --- | --- |
| `data/tiers/T1-2.csv` | Tier 1、2の対象大学院名を取得する。 |
| `data/tiers/T3-4.csv` | Tier 3、4の対象大学院名を取得する。 |

対象校の判定には `大学/大学院名` だけを使用する。`T3-4.csv` には研究科・専攻列がないため、tiers側の研究科・専攻を抽出条件にはしない。

### 大学院

| ファイル | 抽出する情報 |
| --- | --- |
| `2025_09go_H.csv` | 研究科・専攻・学年別の在籍学生数と社会人学生数 |
| `2025_09go_I.csv` | 研究科・専攻別の志願者数と入学者数 |

### 卒業者と就職

| ファイル | 抽出する情報 |
| --- | --- |
| `2025_30go_2_1.csv` | 専攻別の卒業後状況と入学年度別卒業者数 |
| `2025_30go_2_2.csv` | 専攻別の職業別・産業別就職者数 |

入力CSVはすべて `data/univ_portraits_R07/` にあるものを使用する。

## 対象校の抽出

### 大学名の正規化

1. tiersの `大学/大学院名` が空の行と合計行を除外する。
2. 末尾が `大学院` の場合だけ、その文字列を除去する。
3. `北陸先端科学技術大学院大学` と `奈良先端科学技術大学院大学` のように、名称内部に `大学院` を含む大学名は変更しない。
4. `室蘭工業大学` と `室蘭工業大学大学院` のような重複表記を同じ大学へ統合する。
5. 正規化後の大学名をR07の学校名に一致させ、一致後は `学校コード` を主キーとして扱う。
6. あいまい一致は行わない。不一致は自動補正せず、対象校マスタへ理由付きで記録する。

期待値は、tiersの異なる表記が33件、正規化後が32校、R07との一致が23校、不一致が9校である。

### R07にない大学

以下の9校は初期版の抽出対象外とする。

- 千葉工業大学
- 大阪工業大学
- 大阪電気通信大学
- 早稲田大学
- 東京工科大学
- 東京理科大学
- 東京電機大学
- 神奈川工科大学
- 芝浦工業大学

対象校マスタでは `availability` を `unavailable` とし、`exclusion_reason` にR07一括データ未収録であることを記録する。

## 理系研究科の定義

### 分野カテゴリ

各研究科を次のいずれかに分類する。

1. 理学・数学
2. 工学
3. 情報
4. 農学・水産
5. 生命科学
6. 環境・エネルギー
7. 医歯薬・保健・獣医
8. 学際

### 採否の管理

研究科の採否とカテゴリは `target_graduate_schools.csv` で明示する。キーワード判定は候補生成の補助に限り、最終的な採否には使用しない。

次のような研究科は名称だけで自動判定せず、個別に採否と理由を記録する。

- 新領域創成科学研究科
- 環境学研究科
- 人間・環境学研究科
- 総合文化研究科
- 地球環境学舎
- 医農融合公衆衛生学環

`いずれの研究科にも所属しない聴講生・研究生等` は研究科ではないため対象外とする。

### 研究科名の差異

大学院データと卒業者データでは、同じ組織の名称や集計単位が一致しない場合がある。例として、`薬学府（創薬科学）` と `薬学府`、`学際情報学教育部（府）` と `学際情報学教育部`、旧組織名と新組織名が存在する。

研究科マスタは次の列を持ち、入力群ごとの表記を同じ正規名へ対応付ける。

| 列 | 内容 |
| --- | --- |
| `school_code` | R07の学校コード |
| `university_name` | 正規化済み大学名 |
| `canonical_graduate_school_name` | 可視化で使用する研究科の正規名 |
| `source_group` | `09` または `30` |
| `source_graduate_school_name` | 入力CSVにある研究科名 |
| `field_category` | 8種類の分野カテゴリ |
| `included` | 採用可否 |
| `decision_reason` | 採否または名寄せの根拠 |

別名称を自動的な文字列置換で統合せず、学校コードと入力群別の名称を使って明示的に対応付ける。

## 出力構成

```text
data/processed/univ_portraits_R07/
├── target_universities.csv
├── target_graduate_schools.csv
├── graduate/
│   ├── 2025_09go_H.csv
│   └── 2025_09go_I.csv
└── outcomes/
    ├── 2025_30go_2_1.csv
    └── 2025_30go_2_2.csv
```

### 対象校マスタ

`target_universities.csv` は少なくとも次の列を持つ。

- `tier`
- `tier_source`
- `tier_university_name`
- `normalized_university_name`
- `school_code`
- `availability`
- `exclusion_reason`

### 抽出済みCSVの追加列

入力列は削除・改名せず、次の列を末尾に追加する。

- `canonical_university_name`
- `canonical_graduate_school_name`
- `field_category`
- `row_level`
- `source_file`

## 抽出規則

### 共通規則

1. `availability == available` の学校コードに限定する。
2. 研究科名を入力群別の研究科マスタへ完全一致させる。
3. `included == true` の研究科だけを残す。
4. 元の値と列順を維持し、共通メタデータ列を末尾に追加する。
5. 抽出時には人数の再集計や欠損値の補完を行わない。

### 大学院CSV

- `学校コード` で対象校を絞り込む。
- `研究科名` を `source_group == 09` の研究科マスタへ一致させる。
- `2025_09go_H.csv` と `2025_09go_I.csv` では、`専攻 == 計` かつ `符号 == 9999` の行を `graduate_school_total`、それ以外を `major_detail` とする。
- `計算科学` や `環境計画学` などを誤認しないよう、`計` の部分一致は使用しない。

### 卒業者・就職CSV

- `学校種別 == 2` に限定し、学部データを除外する。
- `学校コード` で対象校を絞り込む。
- `学部・研究科名` を `source_group == 30` の研究科マスタへ一致させる。
- `2025_30go_2_1.csv` と `2025_30go_2_2.csv` は専攻明細として `row_level` を `major_detail` とする。

集計レベルをまたいだ合算は前処理では行わない。FastAPI側が用途に応じて一つの `row_level` を選択する前提とする。

## 実装手順

1. pandasを使用する抽出スクリプトを `src/` に追加する。
2. tiersから対象校候補を生成し、R07の学校名・学校コードとの一致結果を対象校マスタへ出力する。
3. 23校の研究科候補を `09` と `30` の入力群から収集する。
4. 候補へ採否、正規研究科名、分野カテゴリ、判断理由を付与し、研究科マスタとして固定する。
5. 4つの入力CSVへ共通規則と入力群別規則を適用する。
6. 抽出済みCSVを所定のディレクトリへ出力する。
7. 検証条件を満たさない場合は出力を成功扱いにせず、不一致内容を表示する。

## 検証

- tiersの33表記、32校、R07一致23校、未収録9校という件数を確認する。
- 抽出行の学校コードが対象校マスタの `available` 行だけに含まれることを確認する。
- 抽出行の研究科名が研究科マスタへ一意に対応することを確認する。
- 採用研究科の `field_category` と `decision_reason` が空でないことを確認する。
- 未対応の研究科名、複数の正規名に一致する研究科名、入力に存在しなくなったマスタ行をエラーにする。
- 各出力の行数が対応する入力の行数以下であることを確認する。
- 元の列名、列順、値が入力行から変化していないことを確認する。
- `graduate_school_total` と `major_detail` を同時に合算しないことをテストする。
- 同じ入力とマスタから再実行した結果が一致することを確認する。

## 私立大学院データの制約

今回使用するR07一括データは国公立版参加大学を対象としている。大学ポートレートの活動概要でも、Web APIの提供対象は国公立版参加大学と説明されている。[大学ポートレート・大学情報基盤センター活動概要2025](https://portraits.niad.ac.jp/files/AnnualReport2025.pdf)

私学版大学ポートレートでは学校・研究科単位の情報を個別に公表しているが、今回のR07データと同様に「大学別・研究科別・専攻別」を一括処理できる構造化データは確認できない。[大学ポートレート私学版の公表単位](https://www.shigaku.go.jp/p_usage_target.htm)

背景資料として、日本私立大学協会附置私学高等教育研究所の公開研究会資料では、共有データの一般公開を好ましくないとする意見や、大学ポートレート掲載情報が公開範囲の限界ではないかという意見が報告されている。[データシェアのニーズ](https://www.shidaikyo.or.jp/riihe/kenkyukai/pdf/70th_no4.pdf)

同研究所の資料では、数値情報が第三者による大学ランキングに利用され得ることも論じられている。これはデータ未提供の直接的な公式理由と断定せず、公開範囲に関する懸念の背景として扱う。[日本私立大学協会附置私学高等教育研究所の研究資料](https://www.shidaikyo.or.jp/riihe/book/series/pdf/037_3-1.pdf)

## 完了条件

- 対象校マスタと研究科マスタの仕様が確定している。
- 4つの入力CSVそれぞれに、再現可能な抽出条件が定義されている。
- 私立9校を抽出しない理由が対象校マスタと文書に記録されている。
- 研究科計と専攻明細の二重計上を防ぐ規則が定義されている。
- 実装者が追加の仕様判断をせず、抽出スクリプトと検証を作成できる。
